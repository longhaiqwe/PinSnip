# GIF 分享大小

菜单栏 PinSnip → **设置 → GIF 分享大小…** 可设置最大宽度、最大高度和文件体积上限。

- **标准**：1280 × 1080 像素以内，15 MB 以内；同时控制在 350 帧、3 亿累计像素以内。
- **小体积**：640 × 640 像素以内，1 MB 以内，适合先尝试向聊天软件分享。
- **原始大小**：不压缩，复制原文件内容。
- **自定义**：宽高可填 128–4096 的整数；体积可填 0.1–50 MB；每项填 0 表示该项不限制。MB 按 1,000,000 字节计算。

设置保存后立即用于录制完成后的复制、晾衣架上的复制，以及桌面贴图菜单中的「复制原动图」。画面保持比例且不会放大；文件超出上限时会进一步降低尺寸或帧率，实际画面尺寸可能小于填写的上限。所有压缩均保留完整播放时长、最后一帧与循环次数。「保存原动图…」仍保存原文件。

压缩在后台进行，准备窗口关闭后再粘贴。压缩失败会提示错误，并保留原剪贴板内容。

晾衣架里的原始录屏不会修改；保存、从晾衣架或访达直接拖出的仍是原文件。

## 复制与拖拽到聊天软件

- 直接单击晾衣架动图或选择「复制动图」，等准备窗口关闭后在聊天输入框粘贴；复制时使用上述压缩设置。
- 从晾衣架拖出时，在同一个拖拽项目中提供原始 GIF 数据与文件地址；拖到访达仍可导出原文件，拖拽不应用复制时的压缩设置。
- 复制和拖拽均提供 `com.compuserve.gif` 与 Qt 的 `com.trolltech.anymime.image--gif`，后者对应 `image/gif`。这些表示使用相同的 GIF 字节，不经过静态图转换。文件地址保留为兼容方式。

不建议通过浏览器的「复制图片」中转动图：该操作可能只提供当前帧。PinSnip 不主动提供 PNG/TIFF 静态替代，但 macOS 仍可在接收应用请求 TIFF 时自动生成静态表示。

小体积预设不保证微信等目标应用会将文件识别为动图。目标应用可以选择文件地址或请求静态图，PinSnip 无法指定其消息类型。Qt 的 GIF MIME 表示已通过字节和动画完整性测试；微信聊天中的实际展示仍需在目标版本中验证，不能仅凭文件体积或自动测试通过判断兼容性。
