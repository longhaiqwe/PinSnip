# PinSnip 产品与交互走查

日期：2026-11-13，北京时间。范围：当前工作区的全部应用界面入口、主要操作和异常恢复路径。

本轮先修正会丢失结果、误触操作或阻断恢复的问题，再检查层级与组件状态。三个子 Agent 分别负责采集、晾衣架与贴图、菜单与设置，主 Agent 整合测试和原生控件预览。

这是一轮基于代码、原生控件和自动化测试的专家走查，没有招募用户，也没有实际任务完成率或情绪体验数据。不能据此认定已经达到行业领先水平。

## 证据与判断范围

- 项目为 AppKit（macOS 原生界面框架）与 SwiftUI（声明式界面框架），不使用网页组件或 Tailwind。继续沿用系统字体、已有布局常量和颜色。截图工具栏固定浅色；其他界面跟随系统外观。
- 使用 `refactoring-ui` 检查信息层级、分组、状态和一致性。表内 `§` 编号对应该技能的设计规则；业务问题另标明具体原则，避免把数据丢失归成审美意见。
- 桌面工具读到了已安装应用的晾衣架结构，但返回的是隐藏面板，截图为空白；菜单栏访问超时。未把这次读取计为完整实际操作验证。
- 隔离预览直接实例化产品中的原生控件，使用合成图片、临时目录和独立偏好设置。没有读取用户截图来制作报告，没有用网页重画产品。
- 原生预览能检查排版和控件状态，不能替代真实桌面的屏幕边缘触发、跨应用拖拽、系统权限、菜单跟踪和多显示器体验。系统弹窗和更新流程本轮只检查代码与已有状态测试。

本报告采用任务风险分级：P1 为本轮应先修的结果丢失、误触、流程错误；P2 为可继续操作但增加理解或恢复成本的问题；P3 为需先测量再决定的优化。优先级是产品判断，不是已测得的用户影响比例。

| H8 | P1 / 一致性、反馈 | 菜单自动验证重新启用“自动下载并安装更新”，关闭自动检查后的禁用状态不可靠 | 验证、显示与执行入口共用同一可用条件 | `validateMenuItem`、`perform`、`UpdateMenuState`；已有条件组合测试，实际菜单未点击 |
| H9 | P2 / 组件一致性、视觉层级 | 箭头样式栏初始化为零尺寸，与三个固定尺寸按钮冲突 | 挂入窗口前设置实际尺寸，与其他样式栏一致 | `SelectionOverlayView`；初轮测试日志复现，最终日志复查 |

同时补齐 GIF 入架、卡片复制、贴图读取失败的可读错误提示。贴图管理器不可用时保留卡片。现有贴图旋转、镜像、缩放只改变显示，“复制原图 / 原动图”仍输出原内容，不把显示变换默默加入导出。

这些修复减少了需要重新截图、重新录制或猜测状态的情况。但“保存取消后的暂存”不等于所有磁盘故障都可恢复；GIF 暂存和最终输出同时失败，仍需要下面的结果重试方案。

## 六个维度的后续方案

下表记录首轮走查提出的改动。实施结果见「后续修复」。

| 编号 / 级别 | 维度、依据 | 位置与问题 | 实施方案 | 验收条件 | 工作量 |

| A10 / P2 | 反馈，§8.4 | 滚动采集失败会停止输出已有部分，但未说明为何中断 | 传递结束原因；结果提示保留了多少段、何处中断 | 模拟权限失效或显示器断开，不把部分结果表述为完整成功 | 中 |
| A11 / P2 | 反馈、一致性，§5.7 | 贴图的透明度、镜像、置顶状态在菜单内没有勾选 | 菜单打开时根据实际状态更新勾选；鼠标穿透提示全局恢复入口 | 各档透明度、两种镜像、置顶状态正确；开启穿透后仍能从菜单恢复 | 小 |
| A12 / P2 | 视觉层级、操作语义，§2.1、§2.8 | GIF 与长图主按钮叫“完成”，实际动作是停止并复制 | 统一可见名称为“复制”或“停止并复制”，同时验证按钮宽度与主次关系 | 浅色/深色/禁用态无截断，图标与文字整体居中；用户不必悬停才知道结果 | 小 |
| A13 / P2 | 组件一致性 | 设置窗口重复打开会重新居中 | 仅首次居中，再次打开只激活，保留用户放置位置 | 拖动窗口、切换应用、重新打开后不跳位 | 小 |
| A14 / P2 | 反馈，§8.4 | 快捷键重复冲突只显示总括错误 | 标出相互重复的两项；系统注册失败按动作定位 | 三种组合冲突均能定位；不覆盖其他已输入的快捷键 | 中 |
| A15 / P3 | 操作效率，待测 | 双击贴图的第一击已经复制，覆盖剪贴板 | 对比立即单击与等待双击间隔两种策略，记录误触与等待成本后选定 | 双击不会意外复制；单击反馈延迟在实测后决定，不凭空给阈值 | 中 |
| A16 / P3 | 操作效率，待测 | 晾衣架展开时，滚动区外 GIF 也可能播放 | 先测多动图内存/CPU与展开耗时；按可见范围暂停 | 相同样本下前后测量，进入可视区域恢复播放，拖拽预览不闪烁 | 中 |

视觉检查保留了已有系统控件和工具栏分组，不增加装饰。当前更需要把状态与结果表达准确。后续视觉验收应把动态背景、不同系统强调色、减少动态效果和读屏状态补入，不能只检查静态浅色截图。

## 验证记录

- Release 测试发现 353 项：349 项通过、4 项跳过、0 失败。跳过项为真实屏幕捕获回退、实时动图帧率、排除录制控制窗、录入本应用窗口；原因均为独立测试进程没有现成的屏幕录制权限。本轮没有重新申请或重置权限。
